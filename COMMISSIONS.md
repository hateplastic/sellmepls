# Комиссии и поиск

Для новых заказов используется тариф версии 2. Для поштучных товаров комиссия рассчитывается один раз от **общей суммы заказа**: цена единицы × количество. Например, 30 × $0.10 = $3.00; платформе $0.65, продавцу $2.35 без партнёрской комиссии.

| Сумма заказа в USD | Платформе | Продавцу без партнёра |
| --- | --- | --- |
| $0.10 | $0.01 | $0.09 |
| $0.60 | $0.06 | $0.54 |
| $2.49 | $0.249 | $2.241 |
| $2.50 | $0.625 | $1.875 |
| $4.99 | $0.7495 | $4.2405 |
| $5.00 | $0.75 | $4.25 |

Строго ниже $2.50 — 10% без фиксированной части. Начиная с $2.50 — 5% + $0.50. Для USDC/USDT расчётная стоимость одного токена равна $1. Для ETH/SOL свежий курс фиксируется при создании заказа; сравнение порога и расчёт выполняются без floating point. Проценты округляются вниз до минимальной единицы токена, фиксированная часть — вверх. Комиссия партнёра дополнительно вычитается из полной цены. Сумма всех комиссий должна оставлять продавцу положительный остаток. Покупатель отдельно оплачивает сетевые расходы.

Заказ хранит `commission_version`, `fee_bps`, `fixed_fee`, курс и итоговые суммы. PostgreSQL проверяет соответствие тарифу. Старые заказы остаются на прежних условиях, включая незавершённые, пока действует их срок. Для новой цены создаётся новый заказ после истечения предыдущего. Подпись котировки EVM и точное сообщение Solana защищают зафиксированные суммы; существующий PaymentRouter принимает подписанную комиссию 10% без изменения ABI.

Поиск находится над товарами, рядом с категорией и сортировкой. Учитываются название и описание, регистр не важен, поддерживаются начала слов и сокращения «тг / tg / Telegram / телеграм». Обрабатываются первые 12 слов запроса длиной до 120 символов; все эти слова должны присутствовать. Семантический поиск и исправление опечаток не реализованы.

Сортировки: новые, цена вверх/вниз, название А–Я/Я–А, оценка покупателей, число отзывов. Фильтры работают вместе и сохраняются в URL при переходе по страницам. Сначала фильтруется и сортируется вся база, затем выдаются страницы по 12 товаров. Скрытые товары исключены. Оценки берутся только из подтверждённых покупок текущего окружения.

Для сравнения цен берётся минимальная из доступных цен товара в приблизительном USD. ETH/SOL пересчитываются по свежему курсу; это не обмен токенов и не платёжная котировка. При недоступном курсе используются известные цены, товары без известной USD-цены идут в конец обеих сортировок. Точная сумма всегда показана в выбранном токене перед оплатой.

Для существующей базы применить после модерации `migrations/20261015_micro_fees.sql` и `migrations/20261015_catalog_search.sql`. Эти миграции уже применены к текущему подключённому проекту. На новой базе достаточно полного `schema.sql`.
