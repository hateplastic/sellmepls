# Подключение сетей

## Подтверждённое развёртывание BSC

Контракт `0x63fcA73531C33d492bc8C1Cc4B7bCaF59BeA0587` зарегистрирован в mainnet по транзакции `0x05bdbb5d5c16cfb98fae3cc4dd401cda35f6a1481319cc3a9dd83589edb10155`. Создание успешно, комиссия составила 0.0000598761 BNB. Проверены код создания и исполнения, получатель комиссии, подписант цены и разрешение USDT BEP20. Покупка товара в BSC ещё не подтверждена этим развёртыванием.

PublicNode возвращал для квитанции `-32602: Archive requests require a personal token`. Основной BSC RPC заменён на `https://bsc-dataseed.bnbchain.org`, добавлен резервный `https://bsc-dataseed-public.bnbchain.org`. Админка подтверждает развёртывание через сервер и хранит хеш в браузере отдельно для каждой сети. Для восстановления без новой транзакции предусмотрен `scripts/recover-deployment.ts network hash --register`, который использует ту же строгую проверку, что API, и требует серверные настройки.

Реализованы Solana (SOL, USDC, USDT), Base (ETH, USDC), Arbitrum (ETH, USDC, USDT0), Ethereum (ETH, USDC, USDT), BNB Smart Chain (Binance-Peg USDT) и TRON (USDT TRC20). Bitcoin отложен. BUSD не добавлен: новые платежи используют поддерживаемые токены. Токен и сеть выбираются вместе, автоматического обмена или моста нет.

BNB Chain USDT имеет **18 знаков**, в Ethereum/TRON/Arbitrum — 6. Binance-Peg USDT — обеспеченный Binance токен, USDT0 в Arbitrum — отдельная реализация USDT0. Их точные адреса закреплены в `lib/catalog.ts`. Комиссия считается от всей суммы заказа: ниже $2.50 — 10%, иначе 5% + $0.50. Сетевые расходы оплачиваются отдельно.

## Включение mainnet

1. Применить `migrations/20261016_multichain.sql` один раз через SQL Editor. Миграция сохраняет существующие товары и покупки, добавляет TRON-адреса, закрытые таблицы входа и новые сети. Не выполнять весь `schema.sql` поверх существующей базы.
2. В `.env.local` используется `NEXT_PUBLIC_CHAIN_ENV=mainnet`. Приватные RPC: `BASE_RPC_URL`, `ARBITRUM_RPC_URL`, `ETHEREUM_RPC_URL`, `BSC_RPC_URL`, `SOLANA_RPC_URL`, `TRON_RPC_URL`. Последние два EVM endpoint и TRON имеют публичные значения по умолчанию. Для нагрузки настройте собственные провайдеры; `TRON_API_KEY` остаётся на сервере.
3. Адрес комиссии TRON: `PLATFORM_TRON_WALLET`. EVM и Solana сохраняют свои адреса. В профиле продавец указывает адрес каждой нужной семьи сетей. Для TRON предусмотрен вход через TronLink с одноразовым подписанным запросом; кошелёк не передаёт приватный ключ.
4. Администратор входит своим существующим EVM/Solana аккаунтом и открывает `/admin`. В каждой EVM-сети один раз создаёт контракт через кошелёк, оплачивая ETH или BNB. В TRON — через TronLink, с TRX для Energy/Bandwidth. **Лимит TRON развёртывания 200 TRX — это потолок, а не обещанная фактическая стоимость.** После подтверждения сохраняет хеш, сервер проверяет исходный код создания и параметры. Сеть остаётся недоступной покупателям, пока контракт не зарегистрирован.
5. Продавец добавляет цену и адрес выплаты; отдельный покупатель проверяет заказ и подписывает оплату. Для USDT/USDC сначала может потребоваться отдельное разрешение ровно суммы заказа, иногда — сброс старого разрешения. Каждая транзакция расходует газ.

## Проверки и границы готовности

`npm run contracts:build` компилирует EVM и TRON разными компиляторами. TRON использует официальный solc 0.8.25 с проверенным SHA-256. `TronPaymentRouterEvmModel.json` предназначен только для локальных тестов логики; он никогда не используется для развёртывания. Исполнение модели в EVM не заменяет проверку TVM/mainnet.

`node --import tsx --conditions=react-server scripts/check-networks.ts` проверяет сети и точность токенов без перевода денег. `npm run preflight` проверяет зарегистрированные контракты и сервисы; отсутствие контракта даёт ошибку готовности.

Новая сеть не считается проверенной реальной покупкой, пока пользователь не развернёт контракт и не выполнит оплату с получением файла. Предыдущая успешная покупка SOL не доказывает работу TRON/EVM. Окончательные подписи оплачиваемых транзакций выполняются владельцем кошелька.

TRON требует подтверждённый solidity-блок. Сервер сверяет отправителя, контракт, событие, токен, суммы, партнёра, срок и уникальность заказа до выдачи файла. Прямой перевод на продавца не является оплатой заказа. Контракт распределяет деньги напрямую и не содержит функции вывода средств администратором.
