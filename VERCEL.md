# Развёртывание Sellmepls на Vercel

Импортируйте hateplastic/sellmepls, корень ./, Framework Next.js, Node.js 24.x.
Используйте Pro: проект коммерческий, расписание в vercel.json запускается каждую минуту.
Команды установки и сборки заданы в vercel.json. npm run build сначала компилирует
контракты, затем собирает Next.js. Сборка не развёртывает контракты и не тратит криптовалюту.
Компилятор TRON скачивается из официального репозитория с проверкой SHA-256.

## Переменные окружения

Перенесите необходимые значения из локальной конфигурации в Settings → Environment
Variables, область Production. Список имён находится в .env.example.
Не подключайте Preview deployments к рабочей базе и рабочим секретам.

- NEXT_PUBLIC_APP_URL: окончательный HTTPS-адрес сайта без завершающего слеша.
- NEXT_PUBLIC_CHAIN_ENV=mainnet; все RPC должны соответствовать mainnet.
- Supabase: URL, публичный ключ и серверный service-role/secret key.
- R2: endpoint, bucket, region, access key и secret key.
- Адреса платформы и администраторов: сохраните действующие значения.
- QUOTE_SIGNER_PRIVATE_KEY: сохраните ключ, соответствующий уже развёрнутым
  контрактам. Произвольная замена сломает проверку подписанных заказов.
- INVENTORY_ENCRYPTION_KEY: сохраните существующий ключ и его защищённую резервную
  копию. Иначе уже загруженные поштучные товары не получится расшифровать.
- REFERRAL_SECRET: сохраните для действующих подписанных переходов.
- CRON_SECRET: случайный серверный секрет длиной не менее 32 символов.

Ранее раскрытые ключи Supabase/R2 отзовите и замените у провайдеров.
Не меняйте ключи шифрования или подписи контрактов как обычные API-ключи.
Адреса зарегистрированных контрактов читаются из payment_routers. При использовании
той же базы повторно развёртывать контракты не нужно.
После изменения переменных выполните Redeploy.

## Адрес сайта и хранилище

В Supabase Authentication → URL Configuration задайте HTTPS Site URL и необходимые
разрешённые адреса перенаправления. Проверьте Web3 Auth.
В CORS приватного R2 bucket разрешите точный origin сайта для PUT/GET/HEAD и заголовки
загрузки. Не открывайте публичный доступ к bucket. Localhost можно оставить отдельно.
Загрузка идёт напрямую в R2, проверка файлов выполняется сервером. Проверьте
максимальный размер файла: вычисление контрольной суммы ограничено временем функции.

## Проверка оплат

Vercel вызывает GET /api/reconcile раз в минуту с Authorization: Bearer CRON_SECRET.
Запрос без точного секрета отклоняется. POST сохранён для внешнего планировщика.
Cron запускается для Production. Локальный launcher/worker для опубликованного
сайта не нужен. Не запускайте бесконечный scripts/worker.ts как Vercel Function.
Контролируйте ошибки, длительность и тайм-ауты в Logs/Cron Jobs.

## Проверки перед открытием продаж

1. Сборка прошла; страницы доступны гостям, Deployment Protection не закрывает Production.
2. Работают вход, создание и редактирование товара, загрузка и превью.
3. Сети, токены, контракты и кошельки выплат соответствуют действующей конфигурации.
4. Проверены небольшой платёж, выдача файла и повторное скачивание в кабинете.
5. Оплата подтверждается после закрытия вкладки; Cron Jobs не падает.
6. Проверены поштучный резерв, партнёрские ссылки и закрытость чужих заказов.

Реальные платежи подписывает владелец кошелька. Сборка сама по себе не доказывает
корректность облачных ключей, CORS или фактическую доставку покупки.

При нехватке места локальную сборку можно запустить с SELLMEPLS_LOW_DISK_BUILD=1.
Этот флаг отключает только webpack-кэш сборки. На Vercel оставьте его незаданным.
