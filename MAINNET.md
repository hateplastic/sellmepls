# Реальная покупка на localhost

Локальная конфигурация переключена на основные сети: Solana mainnet-beta, Base 8453, Arbitrum One 42161. Supabase и приватный R2 подключены. Создание mainnet-заказа проверено без отправки денег; полный денежный цикл ещё должен подтвердить владелец своими кошельками.

Helius подключён через серверный `SOLANA_RPC_URL` в `.env.local`; основная сеть и `getLatestBlockhash` проверены. В браузер RPC-ключ не передаётся. После изменения `.env.local` перезапустите web-сервер и worker. `NEXT_PUBLIC_SOLANA_RPC_URL` больше не используется. Подготовка и отправка проходят через `/api/solana/transaction`, а кошелёк подписывает точные суммы и получателей заказа. При отказе RPC 401/403/429 показывается понятная ошибка без секретного URL; при неопределённом результате отправки сервер сохраняет подпись для сверки.

## Первый платёж через Solana

1. Откройте `http://localhost:3000/dashboard` аккаунтом продавца. В «Профиль и выплаты» сохраните свой Solana-адрес продавца, отличный от адреса платформы. Ранее у существующего товара оба адреса выплат совпадали с платформой — новые кошельки покупателей не устраняли этот конфликт. IP на эту проверку не влияет.
2. Для первой проверки без покупки токенов включите в редакторе `SOL · Solana` и задайте небольшую цену, например `0.001 SOL`. Для отдельной проверки USDC/USDT включите соответствующий токен. Цена в SOL не конвертируется в USDC/USDT; продавец получает SOL. Партнёрскую комиссию для первого теста можно выключить.
3. Нажмите «Сменить аккаунт» на сайте, выберите Phantom · Solana или совместимый Solana-кошелёк и подпишите вход другим адресом покупателя. Переключения аккаунта только в расширении недостаточно.
4. Для оплаты SOL покупателю нужен SOL на цену товара и комиссию сети. Для USDC/USDT нужен именно выбранный токен в Solana, а также SOL на комиссию и создание отсутствующих счетов получателей. SOL-ветка содержит только `SystemProgram.transfer` и memo; токены используют отдельную ветку `transferChecked` с созданием ATA. Во всех случаях `feePayer` — покупатель.
5. Нажмите «Проверить заказ»: сайт получает реальные балансы, стоимость сетевой комиссии и создания счетов, затем симулирует транзакцию без отправки. До подписи показывает нехватку выбранного токена, SOL или минимального остатка на счёте. Для очень маленькой выплаты на пустой адрес получателю может понадобиться предварительное пополнение: [правила баланса счёта Solana](https://solana.com/docs/core/accounts). Расходы считываются из RPC, а не фиксируются как `$0.0008`.
6. Проверьте адреса и сумму, нажмите «Подтвердить оплату в кошельке» и самостоятельно подтвердите перевод. Ниже $2.50 комиссия платформы составляет 10%; от $2.50 — 5% + $0.50. Для поштучных товаров порог применяется к сумме всего заказа. Для цены 0.60 USDC без партнёра: платформе 0.06, продавцу 0.54 USDC.
7. После подтверждения блокчейном появится кнопка скачивания. Повторная загрузка — через «Кабинет → Мои покупки». Подписанная ссылка действует 15 минут, файл скачивается как вложение; ZIP остаётся архивом. Для поштучного товара выдаётся TXT только с закреплёнными за заказом строками.

Не отправляйте обычный перевод вручную: он не содержит идентификатор заказа и разделение платежа. Если вкладка закрылась после оплаты, откройте заказ и восстановите проверку по хешу.

## Включение Base / Arbitrum

Solana использует стандартные инструкции сети; отдельный контракт не нужен. Для EVM один PaymentRouter создаётся в каждой сети:

1. Войдите EVM-адресом администратора и откройте `/admin`.
2. В «Настройка платежей» выберите Base или Arbitrum. На подключённом кошельке нужен ETH в выбранной сети для развёртывания.
3. Нажмите «Создать контракт через кошелёк» и проверьте транзакцию в расширении. Сайт никогда не запрашивает приватный ключ.
4. После двух подтверждений сервер сверит полный deployment input с собранным контрактом, адрес платформы и подписанта, затем сохранит контракт в закрытом реестре Supabase. Сеть станет доступной для покупок. Прерванную настройку можно закончить по хешу развёртывания.

Phantom поддерживает Base и Solana; для Arbitrum используйте совместимый EVM-кошелёк, например MetaMask. Серверные `BASE_PAYMENT_ROUTER` / `ARBITRUM_PAYMENT_ROUTER`, если заданы, имеют приоритет перед реестром. Реестр не разрешает заменять уже подключённый контракт через браузер. Ротация требует отдельной контролируемой операции оператора; старые заказы хранят адрес своего контракта.

## Проверки и работа сервера

```sh
npm run dev
npm run worker
npm run preflight -- solana
npx tsx --conditions=react-server scripts/smoke-checkout.mjs
```

`smoke-checkout` создаёт временные пустые EVM/Solana-аккаунты и товар, проверяет ошибки адресов, цену, комиссию, повторный запрос, серверный blockhash и запрет скачивания без оплаты. Для проверки защиты подписывает намеренно изменённую транзакцию временным пустым кошельком: сервер отклоняет её до отправки в сеть. Реальных переводов нет; свои записи скрипт удаляет. Проверка ZIP/PDF, поддельного файла, скрытия товара, галереи, чата и редактирования: `npx tsx --conditions=react-server scripts/smoke-marketplace.mjs --allow-mainnet-no-payments`, только localhost.

Worker сверяет переданные серверу хеши даже после закрытия вкладки. В production запустите его отдельным процессом или вызывайте защищённый `POST /api/reconcile` по расписанию. Для публичного сайта нужны HTTPS, production Auth URL/redirects и CORS R2 для домена. Телефон не откроет localhost другого компьютера.

Проверка 16 октября: unsigned-симуляции последних SOL-заказов на 0.0001 и 0.001 SOL через настроенный Mainnet RPC завершились без ошибки. Во время проверки комиссия составляла 0.000005 SOL. Это проверка готовности, а не реальная покупка; кошельки пользователя не подписывались, деньги не отправлялись. Скрипт `scripts/diagnose-solana.ts` повторяет диагностику без broadcast. Причина прежнего отказа по одному общему сообщению о балансе не установлена.

Интеграционная проверка склада: `npx tsx --conditions=react-server scripts/smoke-inventory.mjs`. Она использует временные фиктивные строки и пустые кошельки, проверяет резервирование и RLS, затем отдельно моделирует завершённую оплату только собственного тестового заказа для проверки выдачи TXT из R2. Это не доказательство оплаты в блокчейне. Тест удаляет свои записи и файлы; инструкция по настройке склада и ключа шифрования — в `INVENTORY.md`.

Новые поля медиа, реестр контрактов и модерация уже применены к подключённой базе. Для нового развёртывания используйте `schema.sql`; для обновления существующей базы — только ещё не применённые миграции. На товаре доступна обложка + 5 фото + один YouTube URL. Видео воспроизводится с YouTube и не занимает R2.

Список сетей и кошельков с официальными ссылками установки доступен всем на `/wallets`, даже без расширения. EVM обнаруживается через Wagmi/EIP-6963, Solana — через Wallet Standard с проверкой доступных функций и совместимости сети. Браузерное подключение Solflare/Trust реализовано, но проверку реальными расширениями этих двух кошельков ещё нужно выполнить.
